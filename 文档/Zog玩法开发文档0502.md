《Zog 战中存在感与客厅聊天 MVP 开发文档》

目标：  
让 Zog 从“战后附言”变成“玩家的电视搭子”。第一版只做表现层和记忆层，不让 Zog 参与裁判、导演、胜负、数值结算和自动道具消耗。

禁止事项：  
不得让 Zog 成为演员。  
不得新增 Zog actionType。  
不得让 Zog 调用 CombatReferee。  
不得让 Zog 修改 HP、金币、库存、片酬、演员好感、Zog 好感、渡渡鸟数量、鸟群信任、巢区影响力。  
不得让 Zog 自动使用冰箱道具。  
不得把 Zog 逻辑写进 `combatReferee.ts`。  
不得把 Zog 逻辑继续塞进 `battleStore.ts` 的大段流程里。  
不得让 Zog 聊天增加 Zog 好感。当前数值规则是 Zog 好感只通过送礼增加。

允许事项：  
Zog 可以显示在战斗前景。  
Zog 可以对关键事件吐槽。  
Zog 吐槽可以进入 DisplayQueue。  
Zog 吐槽可以进入战报记忆。  
Zog 可以在客厅聊天。  
Zog 客厅聊天可以读取最近一局战斗摘要。  
Zog 可以记录“它好像喜欢哪个演员”，但这个记录第一版不得影响战斗数值。

第一阶段功能：战中 Zog Reaction。

新增类型：

```
export type ZogMood =  | 'idle'  | 'curious'  | 'shocked'  | 'happy'  | 'worried'  | 'disgusted'  | 'confused';export type ZogReactionTrigger =  | 'BIG_DAMAGE'  | 'ACTOR_ELIMINATED'  | 'PLAYER_COMMAND'  | 'ITEM_USED'  | 'LOW_HP'  | 'DODO_SWING'  | 'NEST_SWING'  | 'FINAL_ACTIONS'  | 'BATTLE_END';export interface ZogReaction {  reactionId: string;  battleId: string;  actorActionIndex: number;  trigger: ZogReactionTrigger;  mood: ZogMood;  text: string;  relatedActorIds: string[];  sourceEventIds: string[];  shouldSaveToReport: boolean;  createdAt: number;}
```

新增文件：

```
src/features/zog/zogTypes.tssrc/features/zog/zogReactionRules.tssrc/features/zog/zogReactionService.tssrc/features/zog/zogMemoryStore.tssrc/features/zog/components/ZogForeground.tsx
```

`zogReactionRules.ts` 负责判断触发条件。第一版触发条件如下：

大伤害：单次伤害 >= 20，触发概率 50%。  
演员出局：必定触发。  
玩家上帝指令注入：触发概率 80%。  
玩家使用道具：触发概率 70%。  
演员 HP 低于 25%：触发概率 40%，同一演员 5 个 action 内不要重复。  
渡渡鸟控制数变化 >= 8：触发概率 40%。  
最后 5 次 Actor Action：每 2 次最多触发 1 条。  
战斗结束：保留现有结算 reaction，但改成中文模板。

频率限制：  
每个 Actor Action 最多 1 条 Zog reaction。  
连续 2 个 Actor Action 不要都出 Zog reaction，除非是演员出局。  
整局最多保存 3 条 `shouldSaveToReport = true` 的 Zog reaction。  
Zog reaction 不进入 LLM 结算链路。

模板示例：

```
BIG_DAMAGE:- Zog 把薯片袋抱紧了：“电视里的痛会便宜一点吗？”- Zog 盯着屏幕：“这个人刚才是不是少了一大块节目生命？”ACTOR_ELIMINATED:- Zog 沉默了两秒：“他被节目吃掉了。”- Zog 小声说：“这就是退出频道的方式吗？”PLAYER_COMMAND:- Zog 看向你：“你又对电视施法了。”- Zog 认真点头：“这个指令听起来不像合法遥控器功能。”ITEM_USED:- Zog 看了看冰箱：“我们家原来有急救预算？”- Zog 把爪子缩回来：“我没有偷吃那个罐头。”LOW_HP:- Zog 凑近屏幕：“他还活着，但活得很不省钱。”- Zog 小声说：“要不要……假装我们没看见？”DODO_SWING:- Zog 记录道：“鸟很多的时候，鸟就是天气。”- Zog 震惊：“这些鸟是不是已经成立公司了？”
```

接入方式：

不要在 `combatReferee.ts` 里触发 Zog。  
不要在 ActorBrain 生成后直接塞 Zog。  
推荐在 `BattleEngine` 完成 commit、生成 BattleEvent 后，由外层 feature service 扫描新事件，生成 `ZOG_REACTION_EMITTED` 事件，或直接生成 `DisplayEvent(kind: 'ZOG')`。

考虑当前代码已经支持 `ZOG_REACTION_EMITTED -> DisplayEvent(kind: 'ZOG') -> RenderOp(ZOG_REACTION) -> OverlayLayer.showZog()`，第一版可以复用这条通路。

但请把 `generateZogReaction()` 从 `src/features/reports/zogReaction.ts` 改造成事件驱动版本，或者新建 `src/features/zog/zogReactionService.ts`，不要继续只基于 finalScores。当前函数只有 3 条英文结算模板，不够用。

第二阶段功能：Zog 前景存在感。

新增组件：

```
src/features/zog/components/ZogForeground.tsx
```

组件职责：  
显示 Zog 的前景头像、表情、气泡。  
读取最近一条 ZogReaction。  
根据 mood 切换 CSS 状态或图片资源。  
不读取或修改战斗数值。  
不调用 engine。  
不调用 LLM。

在 `BattlePage.tsx` 中接入：

```
<BattlePixiCanvas ... /><ZogForeground latestReaction={latestZogReaction} />
```

不要把 Zog 画进 ActorLayer。Zog 不是演员。  
可以先用 React 绝对定位做前景，不必第一版进 Pixi。后续再把 Zog 资产迁移到 Pixi OverlayLayer。

第三阶段功能：Zog 战报记忆。

新增规则：  
`shouldSaveToReport = true` 的 ZogReaction，需要进入 `reporterMemory`，类型为 `ZOG_NOTE`。  
每局最多 3 条。  
优先保存：演员出局、玩家救场、玩家上帝指令、大翻盘、Zog 偏心演员濒死。

注意：`BattleReport` 当前已有 `zogReaction` 字段，也能挂 `reporterMemory`。 第一版不用改大结构，只需要让报告页面能展示多条 Zog note。当前单条 `zogReaction` 可以保留作为结算一句话。

第四阶段功能：客厅 Zog 聊天。

新增文件：

```
src/features/zog/zogChatStore.tssrc/features/zog/zogChatProvider.tssrc/features/zog/components/ZogChatPanel.tsx
```

新增类型：

```
export interface ZogChatMessage {  id: string;  role: 'player' | 'zog';  text: string;  createdAt: number;  source?: 'LOUNGE' | 'BATTLE_RECAP' | 'ACTOR_GOSSIP' | 'SYSTEM_HINT';}export interface ZogChatContext {  zogAffection: number;  gold: number;  lastBattleSummary?: {    battleId: string;    winnerName?: string;    mvpName?: string;    biggestIncident?: string;    playerCommandsCount: number;    usedItemCount: number;    favoriteActorHint?: string;  };}
```

客厅聊天入口放在 `LoungePage.tsx` 的 Zog 区域。当前 `LoungePage` 只有乞讨和送礼按钮，聊天入口应该与这些按钮同层，但不要改动金币和好感逻辑。

第一版聊天先做模板，不强制接 LLM。  
输入“刚才节目怎么样”时，Zog 读取最近战报摘要。  
输入“你喜欢谁”时，Zog 根据 `zogMemoryStore.favoriteActorId` 或最近表现给出回答。  
输入普通闲聊时，返回 Zog 人设模板。  
聊天不增加好感。  
聊天不送金币。  
聊天不修改演员好感。  
聊天不改战斗状态。

第五阶段暂不做：Zog 自动使用冰箱道具。

这条明确禁止进入本次开发。原因：冰箱道具会消耗玩家库存和本局道具次数，当前数值规则里库存和道具次数是严肃经济项。  
后续要做，也只能做“Zog 提议救人，玩家确认后执行”，不能第一版自动偷用。

本次验收标准：

战斗中玩家能看到 Zog 前景。  
关键事件发生后，Zog 偶尔吐槽，不刷屏。  
Zog 吐槽进入日志或前景气泡。  
Zog 吐槽不改变任何战斗结果。  
战报里能看到 1 到 3 条 Zog 记忆。  
客厅里能打开 Zog 聊天。  
Zog 能聊最近一场节目。  
Zog 聊天不会增加 Zog 好感。  
没有新增 actionType。  
没有修改 CombatReferee。  
没有让 Zog 自动使用道具。  
`battleStore.ts` 没有继续膨胀出大段 Zog 业务逻辑。

给小 mini 的执行顺序：

第一步，抽出 `features/zog/`，建立类型和模板规则。  
第二步，复用现有 `ZOG_REACTION_EMITTED`、`DisplayEvent(kind:'ZOG')`、`RenderOp(ZOG_REACTION)` 通路。  
第三步，在战斗事件提交后扫描新事件，生成 ZogReaction。  
第四步，做 `ZogForeground`，先用 React 覆盖在战斗画面上。  
第五步，把最多 3 条重要 ZogReaction 写进 reporterMemory。  
第六步，在客厅加 `ZogChatPanel`，先模板化读取最近战报。  
第七步，清理 `battleStore.ts` 中现有的结算 Zog reaction，不要重复触发。

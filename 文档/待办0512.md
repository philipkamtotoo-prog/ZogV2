## P0 当前功能断点

1. 战斗页道具使用 UI 没接完整  （大葱：暂时不处理，等我做完面板）
   当前新版 `BattlePage` 只展示和选中道具槽，没有目标选择，也没有调用 `useItem(itemId, actorId)`。旧 `ItemPanel` 有逻辑但未挂载。

2. 抽卡重连由其他 agent 处理  
   需求保留：抽卡重连应处理 200G、阵容重抽、下注退款、赔率重算、演员好感回滚。目前本任务不改文档和代码。


4. CommandGate 状态机补齐  
   当前主流程没有完整体现 `QUEUED -> JUDGING -> ...`，模型失败也没有统一进入 `SYSTEM_FAILED_REFUND`。

5. CommandGate 输出合同补齐  （大葱：如果补UI就空着）
   文档中的 `feePolicy`、`uiFeedback`、`strength` 等字段目前未进实际类型。需要决定是删掉旧合同，还是补齐类型和 UI。

6. 玩家动作安全点协议补齐  （大葱：判断道具使用后会不会立即加血or生效，如果会，这条就不改了）
   当前 `useItem` 会立即扣本局次数和库存，未完全遵守“玩家意图入队，安全点统一生效”的协议。

7. generationId 追踪补齐  （大葱：向我解释）
   文档提到 LLM 生成任务带 `generationId`，当前 queue/state 没有该字段。

8. `RESOLVING_COMMAND` phase 接入  （大葱：向我解释）
   类型存在，但提交/追问玩家指令时主流程基本没有切到该 phase。

## P1 UI 和可用性

1. Zog 客厅功能入口补齐  （大葱：暂时不做）
   store 已有 `giftZog`、`beg`、`sendChat`，但当前客厅 UI 没有送礼、乞讨、聊天入口。

2. 开发作弊按钮上线前删除  （大葱：备忘）
   客厅 `Cheat +5000G / 全员 +300S` 是开发工具，不属于正式经济系统。

3. Zog 战中反应接入主流程   （大葱：暂时不做）
   `zog_battle_reaction` provider 和 `ZogNoteOverlay` 存在，但主战斗页未挂载事件驱动 Zog 批注。当前主要只有结算 Zog reaction。

4. 战报系统 schema 升级  （大葱：这个不改了）
   `BattleReport` 仍是 flat schema，没有 `version: 2`、`cover`、timeline/highlights/playerInterventions 等结构。

5. ReporterMemory 事件追溯补齐  （大葱：向我解释）
   文档要求 memory 可追溯 eventIds；当前阶段简报、低血量、零鸟等状态型 memory 允许空 eventIds。

6. 阶段简报频率确认  （大葱：不改了）
   当前代码每 8 个 action 触发一次，文档曾写 5 或 10 个 action。需要冻结正式频率。

7. 节目账单按真实消耗展示  （大葱：改）
   当前账单没有按具体道具消耗计费，也缺演员收益、关系变化等完整节目账单信息。

8. Pixi RenderOp 文案表现补齐  （大葱：暂时先不做）
   当前 Pixi 不播放 `ACTOR_LINE`、`BROADCAST`、`REPORTER`、`ZOG` 文本类 RenderOp，只保留数值/状态/道具/变异/Prompt 视觉反馈。

9. DisplayQueue / DisplayLog 文档模型统一  （大葱：向我解释）
   当前 `BattleState` 没有 `displayQueue` 字段；展示事实源是 engine queue + battle store `displayLog`。需要整理架构文档口径。
